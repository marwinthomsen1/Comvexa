## Editability and architecture

`curated-catalog.js` contains the authored recipes. `curated-generate.js` turns a selected recipe into the application's existing validated design document. Every headline, paragraph, geometric illustration, panel, color and photograph remains a native element. Images are individual replaceable elements with proportional cover crops and optional vertical focal placement. Text is fitted with the real browser font metrics before the document is saved.

The gallery imports only lightweight metadata and its precomputed discovery index. The recipe module, image loader and document store load dynamically when customization starts. The loader fetches only photos used by the chosen design and caches successful asset reads. A missing photo produces an error, not an invented image.

Each new copy is an independent schema-v1 document with embedded image data and no mandatory live template reference. It can be grouped and transformed using the existing v2 upgrade path. No document schema, IndexedDB version, connected binding representation or editor/export code was changed for this task. Connected fields can still be attached through the existing editor; the curated gallery does not automatically create connected campaigns.

## Asset sources and rights

- Existing original unbranded Comvexa ImageGen assets: `public/images/previews/fashion.webp`, `food.webp`, `beauty.webp`, `travel.webp`, `motorcycle.webp`. Their original creation is documented in `docs/preview-variety-report.md`. No third-party stock photos, proprietary templates or scraped artwork were introduced.
- Five source photographs are reused where appropriate, rather than claiming 100 different photos. Typography-led designs deliberately avoid unrelated filler imagery.
- All new graphic artwork is original editable rectangle/ellipse/text composition authored in this repository. Decorative circles and geometry are elements, not flattened template screenshots.
- Arial, Georgia and Courier New use the existing system-font support. No font files were downloaded or redistributed; availability and exact metrics depend on the device. Gallery UI uses the existing project icon system.
- Gallery thumbnails are derived from actual exported native documents and optimized to 480px WebP. Full document exports are never loaded for marketplace browsing.

## Performance measurements

- Metadata file: **32,317 bytes** uncompressed; excludes layout commands and full-resolution assets.
- All 100 WebP thumbnails: **1,518,190 bytes** combined; largest **73,374 bytes**.
- Measured desktop iframe: viewport/document width both **1414px**, **24** cards mounted, **10** thumbnail resources loaded at capture, **47,966 bytes** transferred according to ResourceTiming, **0** full-resolution photo requests.
- After switching that same frame to phone width: viewport/document width both **388px**, **24** cards, **21 cumulative** thumbnail requests and **118,528 cumulative transferred bytes**, **0** full-resolution photo requests. No page horizontal overflow.
- 5,000 metadata filter passes: **23ms** desktop capture, **30ms** phone-width capture. This microbenchmark is not full React rendering or input latency.

These are local development-server measurements in an existing Safari session. Cached resources can report zero transfer size; mobile values include earlier desktop requests. They are not cold-cache production LCP, network-throttled benchmarks or physical-device memory/FPS tests. `docs/template-review/performance.json` records the evidence and caveats.

## Remaining limits

There are five reused photographic subjects, no new stock library, no newly bundled fonts and no true editable gradient-fill primitive. “Colorful” uses editable coordinated color geometry rather than introducing an incompatible gradient schema. The earlier automatic package builder is preserved rather than redesigned. New curated designs start independently and can be connected manually. Per-format reflow, richer photo diversity, production cold-load profiling and physical-device QA remain sensible follow-up work, subject to approval. No unrelated stage has begun.
