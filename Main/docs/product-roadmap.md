# Expanded product vision and development roadmap

Status: proposal for review, November 12, 2026. Reviewed against Phase 5 commit `74c1478`. This document authorizes no implementation, service purchase, monetization or deployment. Phases 1–5 remain completed. Phase 6 remains testing, optimization, reliability and security; Phase 7 remains public-launch preparation.

## Product direction

**Create once. Use everywhere.** Build a worldwide creative platform with the long-term breadth to compete with Canva, starting with an exceptionally reliable campaign-to-multiple-design workflow. Expand the graphic editor before introducing separate product categories. Keep standard editing, basic templates and standard image exports useful for free users, without standard-export watermarks or mandatory AI subscriptions. Premium AI, processing and storage are possible later decisions, not approved pricing.

Comvexa currently supports a small, editable, browser-local graphic-design workflow. It is not yet a general replacement for Canva. No claim of superiority, cloud backup, production authentication or broad feature parity is justified. Measure advantages through actual task success, time, export fidelity, cost and beginner comprehension.

This is the current forward roadmap. Earlier reports remain historical records; `architecture.md` describes the canceled learning-platform direction, and `creative-architecture.md` records the Phase 2 foundation. Neither should be used as the current completion inventory. [Phase 5 report](phase-5-report.md) remains the implementation evidence. See [competitive matrix](canva-feature-matrix.md) for researched comparisons.

## Architecture review: implemented versus missing

Reviewed `src/lib/design-document/schema.js`, editor document/commands/export/images/store/database, connected model/store, editor UI, template catalog/generator, and the Phase 3–5 reports. No application files or dependencies were changed for this review.

| Area | Implemented at Phase 5 | Technical limitation and consequence |
| --- | --- | --- |
| Document | Application-owned schema v1; one canvas, flat elements, stable element IDs, assets, provenance and bindings | No pages, groups, paths, text runs, timings or media tracks. Adding a UI alone cannot supply these features; validator and every renderer/importer must evolve together. |
| Editor | React Konva; text, image, rectangle, ellipse; transform/crop, locking/layers, basic guides, undo/redo | Four allowed fonts (Arial, Georgia, Verdana, Courier New); plain text per element; no custom font ingestion, rich text, effects stack, grouping or multi-selection workflow. |
| Limits | Canvas 64–4096 px each side; 100 elements; 30 embedded assets; 20 MiB document; 24-megapixel image budget; 8 MiB source upload | Appropriate protective limits for this stage, not evidence of scalable professional documents. Do not simply raise limits: decoded images, canvas layers, histories and previews multiply memory. |
| Assets | Validated local PNG/JPEG/WebP, local optimization, embedded data URLs | Repeated bytes across documents/campaigns; no reusable asset library, font registry, media proxies or object cleanup. SVG/HTML and animated uploads rejected intentionally. |
| Saving | IndexedDB v2 designs/packages; separate planning/profile localStorage; editor debounce 800 ms; revision checks | No account, cloud backup or cross-device sync. Separate metadata systems can diverge. Connected snapshots read whole stores, so operation cost grows with the library. |
| History | Bounded immutable snapshots, up to 30 past states with an asset-source budget | Session undo is not persistent version history. Whole-document history is unsuitable as the collaboration protocol. |
| Connected content | Stable campaign/field IDs, typed text/image values, canonical revision, explicit overrides including empty values, atomic linked updates | One campaign per design; no cross-campaign branding graph, schedules or external data feed. Currency does not reformat a price string. Geometric crop adaptation is not subject-aware. |
| Templates | 32 editable compositions: eight families × four ratios; campaign package generation and additional designs | Curated layout generation is not arbitrary smart resizing, a large professional template marketplace or a reusable user-defined style system. |
| Exports | Consistent campaign snapshot, separate artwork-only PNG/JPG renderer, font/image readiness | Raster export at document size, opaque background; no true vector SVG/PDF, print color management, editable PPTX, page batches or video. A4 pixel preset does not certify print production. |
| Security | Client input/image validation; disabled cloud endpoints; prepared ownership/RLS SQL tested in PGlite | No deployed verified identity or hosted Storage/RLS verification. Browser-local separation is not multi-user authorization. |
| QA | Phase 5: 40 tests, lint/build, 17 HTTP cases, Safari/Edge acceptance and 16 checked image exports | Prior evidence, not a rerun in this documentation task. Physical mobile/tablet testing, complete multi-file picker coverage, large-library stress and broader accessibility remain incomplete. |

Keep Konva for the current editor. It supports groups, clipping, filters and animation primitives, but those library capabilities are not implemented Comvexa features. Its canvas renderer does not automatically deliver semantic documents, vector export or a video engine. [Konva overview](https://konvajs.org/docs/overview.html), [performance guidance](https://konvajs.org/docs/performance/All_Performance_Tips.html).

## Proposed architecture changes, staged rather than rewritten

These are design recommendations requiring review and scoped implementation plans.

1. **Storage/repository seam first.** Preserve pure document commands and connected resolution. Define repository interfaces for documents, campaigns, assets and revisions, retaining IndexedDB as one adapter. Add indexed campaign membership and consolidate planning/editor metadata through explicit mapping. Introduce immutable asset IDs/content hashes, Blob-backed local storage, reference counts and safe garbage collection. Never remove assets referenced by history, overrides or backups. Keep legacy embedded-project import/export adapters.
2. **Versioned multi-page model.** A future schema v2 should contain stable `pageIds`/page order, page size/background and element IDs. Migrate v1 into one page deterministically, preserving IDs/bindings/layout. Use staged migration with backup and transaction rollback, fixtures and original-byte retention on error. Older clients must reject unsupported versions without overwriting them. Limit per-page and aggregate resource use; virtualize offscreen pages. Add capability-versioned exports rather than flattening everything to Konva serialization.
3. **Structured scene graph and text.** Introduce group IDs/parent relationships, cycle detection, transforms and selection transactions before vector editing. Add text runs, shared font metrics and a licensed font registry with loading/fallback errors. Layout computation must be shared by interactive previews and export. Canvas accessibility requires semantic DOM controls and text editing alternatives, not canvas labels alone.
4. **Export adapters.** Share resolved scene data and font metrics across preview/raster/vector/presentation adapters. A raster-in-PDF option must be labeled as such; selectable/vector PDF and SVG need explicit implementations, supported-effect rules, font licensing and parity tests. PPTX may require fallback rasterization for unsupported effects; report editability limitations. Never imply universal roundtrip fidelity. Review candidate libraries/licenses in a spike before adoption.
5. **Animation separate from UI motion.** Add a deterministic project clock, duration, element tracks/keyframes/easing and property evaluation `sceneAt(time)`. Current homepage ribbons and preview fades are UI decoration, not exportable animation. Keep transient playback/selection out of saved artwork. Start with bounded animated text/shapes, then build media.
6. **Video/media pipeline.** Store video/audio asset IDs, metadata/proxies and trim/split references rather than frame data inside JSON. Add timeline tracks, rational timestamps, audio synchronization, captions, cancellation, progress and output budgets. WebCodecs is a candidate for frame processing; mux/demux and codec/device support need separate validation. Benchmark browser encoding against isolated server jobs before promising MP4/GIF on phones. [MDN WebCodecs](https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API), [Chrome processing guide](https://developer.chrome.com/docs/web-platform/best-practices/webcodecs).
7. **Collaboration only after identity and cloud ownership.** Establish workspaces, membership/roles, private asset policies, comments and verified sessions first. Then prototype per-element/per-field operations with a CRDT candidate such as Yjs. Whole-document revision rejection remains appropriate today but is not real-time merging. Specify concurrent delete/edit, layer-order, campaign-update and override semantics; campaign revision snapshots must still yield consistent exports. Presence is ephemeral; persist document operations/checkpoints separately. CRDT merge does not enforce authorization or business invariants. [Yjs](https://docs.yjs.dev/), [awareness](https://docs.yjs.dev/getting-started/adding-awareness).
8. **Optional AI gateway.** Server-held credentials, authenticated requests, provider adapters, bounded inputs/outputs, atomic quota reservations, idempotency, retry/cancellation reconciliation, per-user/global caps and kill switch. Review retention, consent, model licenses and quality before selecting a vendor. AI output is untrusted structured content validated by the same schema. Never send private assets without a clear user action and disclosed processing destination. Keep deterministic templates available without AI.
9. **Web/document modules.** Websites need a constrained semantic responsive block model and separate renderer/publishing boundary, not a screenshot of a design. Rich documents need flowing text, pagination, accessibility and print layout; reuse assets/styles but avoid forcing them into an absolutely positioned poster model. Published content needs abuse controls and tenant isolation before public hosting.

Do not preemptively implement v2, a CRDT, a media service or a plugin framework in Phase 6. Record interfaces and benchmarks first; implement migrations when an approved feature requires them.

## Before public launch: recommended scope and gates

Recommend a **limited browser-local beta** first if recovery and usability gates pass. Market it explicitly as a local campaign-design tool with editable packages, not a full Canva replacement. A worldwide account-based launch is a different scope: separate approved development infrastructure, verified auth, private asset ownership and backup/restore are blockers for that scope. Do not enable cloud merely by adding environment variables to the current UI.

Phase 6 should demonstrate: no silent loss in quota/conflict/restart/import tests; exported prices match campaign snapshots; keyboard-only creation/edit/export; phone/tablet workflows on physical iOS Safari and Android Chrome; complete native single/multiple upload testing; image memory stress; safe validation of malformed references and imports; dependency and security-header review. Retain the Phase 5 motorcycle regression and all historical fixtures. Proposed performance targets, to measure rather than claim today: interactive edit input under 100 ms at the 95th percentile on nominated devices within supported limits; first useful editor interaction within 3 seconds on a documented mid-tier device/network; no crash or lost save in maximum-supported-document/export runs. Revise support limits if measurements fail.

Phase 7 should supply truthful feature/coming-soon copy, beginner onboarding and backup explanation, ownership/privacy/licensing notices, support contact, consent for diagnostics, release/rollback instructions, incident recovery rehearsal and a published device/format support list. Conduct at least 8–12 beginner task sessions (more for diverse language/device coverage); require completion of package creation→price update→override→export without assistance in at least 80% of sessions as an initial usability gate. This sample is directional, not statistically sufficient to claim superiority.

Defer video, AI, real-time collaboration, websites, deep vector work and full presentations until after the supported launch scope is reliable. A small professional template collection and clear connected-update/override controls matter more at launch than category breadth. If initial customers require PDF, approve a separately scoped and clearly labeled export increment before promising print workflows; do not silently turn Phase 6 into feature expansion.

## Technical, financial and product risks

| Risk | Exposure | Mitigation / decision |
| --- | --- | --- |
| Asset duplication and mobile memory | High: embedded base64, full-store reads, previews, histories and canvas can exhaust memory before file limits | Profile first; Blob assets, indexed reads, preview virtualization, decode disposal, aggregate budgets and recovery |
| Schema and export divergence | High: new nodes/effects/pages can open but export differently | Shared scene evaluation; golden fixtures across every adapter; staged backups/migrations; capability checks |
| Concurrent connected updates | High: future network fanout cannot reuse a single local IndexedDB transaction | Server revisions and idempotent jobs; pin campaign version for render; explicit staged publication/rollback; test partial failure |
| Collaboration complexity | Very high: merge semantics, auth revocation, offline replay and versions | Prototype isolated operations; avoid wholesale CRDT rewrite; server authorization regardless of client merge |
| Fonts and creative assets | High: copyright, embedding rights, user uploads and vendor terms | Original/licensed assets with provenance; font licenses reviewed; user rights and takedown process; no copied Canva templates/code/branding |
| AI and media spend | High and usage-dependent; abusive retries/large uploads can dominate | Server-enforced budgets, reservations/queues, quotas and concurrency; opt-in expensive tools; no subscription dependency for core editing |
| Print/PPTX fidelity | High: raster versus vector, font substitution, color/bleed and effect compatibility | Scope supported output subsets, explicit limitations and real external-reader/printer checks |
| Scope dilution | Very high for a small team | Freeze milestones around supported user tasks; no breadth claim before demonstrated capability; review usage before new category |

### Budget model (planning assumptions, USD, not vendor quotes)

No purchases are authorized. Current client-side editing has no paid rendering API requirement, but public hosting, bandwidth, support, legal review, testing devices and developer time are not free. Free user features still need a sustainable resource budget.

For a local-only beta, reserve approximately **$30–150/month** for hosting/observability/domain/support tooling at low traffic; confirm actual providers, regions, commercial terms and caps in Phase 7. For a small cloud beta, reserve **$100–500/month** before AI/video, with explicit usage assumptions and alarms; this is a planning allowance, not a promise. As a reference only, Supabase currently lists Pro from $25/month, additional project charges and usage overages. Separate dev/staging and production costs, backup retention and object recovery must be counted. [Supabase pricing](https://supabase.com/pricing).

Worked storage example: 1,000 monthly users × 20 retained designs × 2 MB unique asset bytes = about **40 GB** before history/backups; 10 downloads × 2 MB each per user = **20 GB/month** egress. This assumes real asset deduplication and excludes previews/media; the current repeated-data-URL model can consume more. Use measured unique bytes, not design JSON count, for forecasts.

Optional compute formula: monthly cost = fixed services + stored GB × storage rate + delivered GB × egress rate + job-minutes × compute rate + AI completed/retried calls × unit cost + email/monitoring/support. At an assumed $0.05–0.50/image, 10,000 image calls imply **$500–5,000**; at assumed $0.02–0.20/render-minute, 10,000 output minutes imply **$200–2,000** before retries/storage. These are sensitivity scenarios, **not researched provider prices or product prices**. Benchmark real workload/vendor rates before approving AI/video. Set zero spend until approved, then explicit hard monthly/user caps and a kill switch; alerts alone are not a hard cap.

Labor dominates early cost: approved engineer-weeks × a negotiated weekly rate, plus design/QA/security/legal review and a **25–40% contingency** for uncertain migrations/media/collaboration work. Do not convert the table to a funded budget without staffing, acceptance scope and vendor decisions. No monetization implementation is proposed here.

## Competitive validation and next review decision

Canva documents bulk generation, multi-format designs, AI/photo tools, collaboration and a wide Visual Suite. Comvexa's potential advantage is a clearer and more dependable connected campaign workflow for specific users, not an unverified exclusive feature. Test the same licensed, original-content tasks in both tools: one campaign/four ratios, shared price/photo update, one override, reopen and export. Record median/p95 task time, error rate, override loss, clicks, beginner completion, export fidelity and total paid processing required. Separate first-use learning from repeat-use speed; publish methodology before comparative claims.

Requested review decisions: approve or revise the milestone order; choose a local-only beta versus a separately scoped cloud launch; confirm the supported prelaunch task/device set; approve Phase 6 as reliability work only. This document does not start Phase 6 or any major implementation. The live domain, production and Supabase remain untouched.
